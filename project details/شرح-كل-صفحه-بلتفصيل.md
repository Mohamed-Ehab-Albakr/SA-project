4. Detailed Page Description

Page 1: index.html

Page Name

Login and Registration Page

Functional Requirements

• FR-01: Patient Registration
• FR-02: User Login

Purpose

This is the entry point of the website. Users can create a new patient account or log in using an existing account.

The same page will be used by Patients, Doctors, and Administrators.

HTML Structure

The page can be divided into the following sections:

1. Header:
  • Website logo.
  • Website name.
2. Main Content:
  • Login form.
  • Registration form.
  • User role selector.
3. Footer:
  • Basic website information.

Main HTML Elements

|Element|Purpose                         |
|-------|--------------------------------|
|header |Website header                  |
|main   |Main page content               |
|section|Login and Registration sections |
|form   |User input forms                |
|input  |Name, email, and password fields|
|select |Select user role                |
|button |Login and Register actions      |

FR-01: Patient Registration

Allows a new patient to create an account.

Required fields:

• Full Name
• Email
• Password
• Confirm Password

JavaScript Functionality

1. Read the values entered by the user.
2. Check that all required fields are completed.
3. Validate that the password and confirmation match.
4. Check whether the email is already registered.
5. Save the new patient information.
6. Display a success message.

FR-02: User Login

Allows registered users to access the system.

The user selects their role:

• Patient
• Doctor
• Administrator

JavaScript Functionality

1. Read the email and password.
2. Find the matching account.
3. Check the selected role.
4. Save the logged-in user as the current user.
5. Redirect the user to the correct dashboard.

Navigation

• Patient → patient-dashboard.html
• Doctor → doctor-dashboard.html
• Administrator → admin-dashboard.html

Allows patients to book an appointment with a selected doctor.

JavaScript Functionality

1. Read the selected doctor ID.
2. Read the current patient ID.
3. Read the selected date.
4. Read the selected time.
5. Validate the entered information.
6. Create a new appointment object.
7. Save the appointment.
8. Display a success message.

Example:

let newAppointment = {
    id: 101,
    patientId: 1,
    doctorId: 1,
    date: "2026-11-25",

    status: "Confirmed"

FR-10: Check Appointment Availability

Prevents two patients from booking the same doctor at the same date and time.

JavaScript Functionality

1. Read all existing appointments.
2. Search for an appointment with the same doctor ID, date, and time.
3. Ignore cancelled appointments.
4. If the slot is already booked, display an error.
5. Otherwise, allow the booking to continue.

Example:

let alreadyBooked = appointments.some(function(item) {
    return item.doctorId === selectedDoctorId &&
           item.date === selectedDate &&
           item.time === selectedTime &&
           item.status !== "Cancelled";
});

6. Shared Data Structure

All pages must use the same data structure to avoid conflicts between team members.

The main data collections are:

|Data Name   |Purpose                  |Used By                                |
|------------|-------------------------|---------------------------------------|
|users       |Store user accounts      |Login, Registration, Admin             |
|currentUser |Store the logged-in user |All dashboards                         |
|doctors     |Store doctor information |Doctors, Profiles, Booking, Admin      |
|specialties |Store medical specialties|Doctors, Admin                         |
|appointments|Store appointment records|Booking, My Appointments, Doctor, Admin|

6.1 Users Data

Example:

let users = [
    {
        id: 1,
        name: "Ahmed Ali",
        email: "ahmed@gmail.com",
        password: "1234",
        role: "patient"
    }
];

The role can be:

• patient
• doctor
• admin

6.2 Doctors Data

Example:

let doctors = [
    {
        id: 1,
        name: "Dr. Ahmed Ali",
        specialty: "Cardiology",
        experience: 8,
        workingDays: ["Sunday", "Tuesday"],
        availableSlots: ["10 AM", "11 AM", "12 PM"]
    }
];

6.3 Appointments Data

Example:

let appointments = [
    {
        id: 101,
        patientId: 1,
        doctorId: 1,
        date: "2026-11-25",
        time: "10 AM",
        status: "Confirmed"
    }
];

Why Do We Use IDs?

The patient ID and doctor ID connect the appointment to the correct users.

For example:

• Patient Dashboard filters appointments by patientId.
• Doctor Dashboard filters appointments by doctorId.
• Admin Dashboard displays all appointments.

This allows the same appointment record to be displayed in different pages.

7. Local Storage

Since this is a Front-End-only project, Local Storage can be used to save demonstration data in the browser.

Example:

localStorage.setItem("users", JSON.stringify(users));

To retrieve the data:

let users = JSON.parse(localStorage.getItem("users")) || [];

To save appointments:

localStorage.setItem("appointments", JSON.stringify(appointments));

To retrieve appointments:

let appointments =
    JSON.parse(localStorage.getItem("appointments")) || [];

Important Notes

• Local Storage is used here as a simple demonstration storage mechanism.
• It is not a real database.
• It does not provide secure authentication.
• Passwords and real medical information must not be stored this way in a production application.
• The team should agree on one consistent storage format.

9. JavaScript Organization

The project can use one shared JavaScript file called script.js.

Each HTML page should include the same file before the closing body tag.

Example:

<script src="script.js"></script>
</body>

To identify the current page, each body can have a unique ID.

Examples:

In index.html:

<body id="login-page">

In doctors.html:

<body id="doctors-page">

In booking.html:

<body id="booking-page">

Basic script.js Structure

let currentPage = document.body.id;

if (currentPage === "login-page") {
    // Login and Registration functions
}

if (currentPage === "patient-page") {
    // Patient dashboard functions
}

if (currentPage === "doctors-page") {
    // Search and Filter functions
}

if (currentPage === "profile-page") {
    // Doctor profile functions
}

if (currentPage === "schedule-page") {
    // Doctor schedule functions
}

if (currentPage === "booking-page") {
    // Booking functions
}

if (currentPage === "appointments-page") {
    // View and Cancel functions
}

if (currentPage === "doctor-page") {
    // Doctor dashboard functions
}

if (currentPage === "admin-page") {
    // Admin dashboard functions
}

Every member must agree on the body IDs and function names before implementation.

The shared script should also initialize common data consistently. Avoid declaring the same global variables or initializing sample data differently on every page.
